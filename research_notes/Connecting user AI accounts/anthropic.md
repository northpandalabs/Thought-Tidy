## 1. Anthropic's policy on using Claude Free/Pro/Max/Ultra subscription OAuth tokens in third-party apps (exact text, history, revisions)

### Takeaway
The current Claude Code Legal and Compliance page (fetched 2026-11-18) says subscription OAuth is "intended exclusively" for subscribers using Claude Code and other native Anthropic apps. It bans third-party developers from offering Claude.ai login or routing requests through Free/Pro/Max/Ultra credentials "on behalf of their users". It also bans developers from collecting, storing, or intermediating Claude.ai credentials or session tokens. The policy was first documented around 2026-02-19 after server-side blocking began 2026-01-09. Enforcement reached OpenClaw-style harnesses 2026-04-04. The current text is broader than the February version: it adds Ultra, the "collect, store, or intermediate" sentence, and a section on embedding Claude Code. A secondary source dates that rewrite to 2026-10-07, but I could not confirm the date from a primary source.

### Cited Findings

- Current verbatim text: "**Developers** building products or services that interact with Claude's capabilities, including those using the Agent SDK, should use API key authentication through Claude Console or a supported cloud provider. Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, Max, or Ultra plan credentials on behalf of their users. Moreover, developers may not collect, store, or intermediate Claude.ai credentials or session tokens -- sign-in to a Claude account must complete through Anthropic's own flow." -- [Claude Code Docs: Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)

### Inferences
- For Thought Tidy, any "Sign in with Claude (Pro/Max)" button that obtains a claude.ai OAuth token is squarely prohibited. This covers reusing Claude Code's OAuth client ID, asking users to paste `claude setup-token` output, and reading `~/.claude/.credentials.json`. The "collect, store, or intermediate" sentence covers even the paste-a-token variant.
- Paid Pro features and the hosted subscription make Thought Tidy a "product or service", so the developer clause applies regardless of being source-available.
- Users pasting their own Console API key remains explicitly sanctioned. It is the "preferred" path.

## 2. Official "Sign in with Claude" / OAuth for third-party developers; Console OAuth that provisions billing on the user's behalf; partner programs

### Takeaway
Yes, as of November 2026 there is an official mechanism: **Claude Platform OAuth with "Linked billing"** (Beta). It is the closest analogue to OpenRouter's PKCE flow. A user clicks "Link your Claude organization", signs in at auth.claude.com, sets an optional monthly spend cap, and approves. The app's usage is then billed to the user's **Claude Console (API) organization**, not their Pro/Max subscription. It does not hand the app an API key. Requests are made by the app's own back end, which authenticates with Workload Identity Federation. It is therefore not usable purely from an extension or Electron client without a server. Publishing requires Anthropic review.

### Cited Findings
- "Claude Platform OAuth lets your users bill their Claude organization for usage within your app ... Your users click a **Link your Claude organization** button, sign in to Claude, and approve your app. For Linked billing, the user must have the Admin or Billing role in their Claude organization." -- [Claude Platform Docs: Claude Platform OAuth](https://platform.claude.com/docs/en/manage-claude/oauth-apps/overview)
- Beta: "Claude Platform OAuth is a Beta Service ... Endpoints, parameters, and behavior can change during the beta. It might not be suitable for production use." -- [Claude Platform Docs: Claude Platform OAuth](https://platform.claude.com/docs/en/manage-claude/oauth-apps/overview)
- Protocol: "Claude Platform OAuth uses the OAuth 2.0 authorization code flow with PKCE, with Anthropic as the authorization server." -- [Claude Platform Docs: Claude Platform OAuth](https://platform.claude.com/docs/en/manage-claude/oauth-apps/overview)
- No client secrets: "Instead of a client secret, your back end proves that a request comes from your app with a short-lived token from your own identity provider, such as AWS, Google Cloud, Microsoft Entra ID, or Kubernetes". An operator service account must be set up via Workload Identity Federation. -- [Claude Platform Docs: Claude Platform OAuth](https://platform.claude.com/docs/en/manage-claude/oauth-apps/overview)
- Flow details: `POST /v1/user_profiles` (one profile per customer org). Pushed authorization request to `https://auth.claude.com/v1/oauth/par` with `scope: "billing:attribution"` and a PKCE challenge (request_uri valid 600 s). Redirect to `auth.claude.com/oauth/authorize`. Exchange the code (valid 5 min) at `/v1/oauth/token`, which returns `connection_id` plus an access token. -- [Claude Platform Docs: Linked billing](https://platform.claude.com/docs/en/manage-claude/oauth-apps/organization-billing-connections)
- Request shape: beta header `anthropic-beta: user-profiles-billing-2026-10-01`, header `anthropic-user-profile-id: uprof_...`, and body `billing_policy: {type: "billing_policy", bill_to: "user_profile" | "self"}`. Supported on `/v1/messages` and `/v1/chat/completions`. Message Batches are not supported for customer billing, and billable code execution returns 400. -- [Claude Platform Docs: Linked billing](https://platform.claude.com/docs/en/manage-claude/oauth-apps/organization-billing-connections)
- Credentials: requests are signed by the app's operator service account. The doc says "Ensure `ANTHROPIC_API_KEY` is not set, because your app needs to authenticate with Workload Identity Federation". Connection-bound access tokens "can bill only that connection's customer. It expires within 1 hour". Refresh tokens are issued only with `offline_access`, and the doc says to keep them in a secret store. -- [Claude Platform Docs: Linked billing](https://platform.claude.com/docs/en/manage-claude/oauth-apps/organization-billing-connections)
- Developer obligation: "Set `bill_to: "user_profile"` only on requests the customer directs you to make... Don't bill a customer for your own usage ... The Claude API can't check this for you, so it's your responsibility." Also: "You may bill a customer only for the requests they direct you to make, never for your own usage." -- [Linked billing](https://platform.claude.com/docs/en/manage-claude/oauth-apps/organization-billing-connections); [OAuth overview](https://platform.claude.com/docs/en/manage-claude/oauth-apps/overview)
- Eligibility (user side): the org must be billed directly by Anthropic. Bedrock/Vertex/Foundry orgs and cloud-marketplace-billed orgs cannot link. "Claude subscription plans (Pro, Max, Ultra, Team, and Enterprise) can't be linked". Max/Ultra/Team monthly API credits and partner/VC/startup credits cannot pay for linked usage. Free Console signup is possible during linking, but credits must be added first. -- [Claude Help Center: Use your Claude Platform account in a third-party app](https://support.claude.com/en/articles/18467148-use-your-claude-platform-account-in-a-third-party-app)
- User UX: (1) click the link button, (2) sign in and pick an org, (3) set a monthly spend limit or skip, with apps in testing requiring a limit of $50 or less, (4) the approval screen shows the app name and billing permission, (5) "Link and authorize". Admin/Billing members get a confirmation email. -- [Claude Help Center: Use your Claude Platform account in a third-party app](https://support.claude.com/en/articles/18467148-use-your-claude-platform-account-in-a-third-party-app)
- Spend limits are per app, whole dollars from $1, and $0 blocks the app. Emails go out at 80% and 100%. Limits reset on the 1st (UTC) and are not exact. A 402 is returned when nothing can pay. Unlinking happens in the Console "Linked platforms" page, and new calls stop within about 10 s. -- [Claude Help Center](https://support.claude.com/en/articles/18467148-use-your-claude-platform-account-in-a-third-party-app); [Linked billing docs](https://platform.claude.com/docs/en/manage-claude/oauth-apps/organization-billing-connections)
- Data and terms: requests run in the app's org, so the app's rate limits, model access, and retention apply, and the customer's ZDR/BAA/CMEK do not. "Don't link customers that need HIPAA, FERPA, or CMEK coverage". "The app never receives your API key or your Claude password." -- [Linked billing docs](https://platform.claude.com/docs/en/manage-claude/oauth-apps/organization-billing-connections); [Help Center](https://support.claude.com/en/articles/18467148-use-your-claude-platform-account-in-a-third-party-app)
- Publishing: new apps start as "Test users only". Orgs with invoiced billing publish immediately. Others need DNS TXT domain verification plus Anthropic review ("In review" / "Not approved"). Linked Billing Terms apply, and changing name, logo, or redirect URIs triggers re-review. -- [Linked billing docs](https://platform.claude.com/docs/en/manage-claude/oauth-apps/organization-billing-connections)
- Launch date and partners (secondary): beta launched 2026-11-17 and was announced by @ClaudeDevs. Early partners named: Factory, Linear, Ramp. -- [Emergent news](https://emergent.sh/news/claude-linked-billing-lets-third-party-tools) (secondary); Railway also announced support -- [Railway blog](https://blog.railway.com/p/linked-billing-claude-platform)
- Help Center developer guidance: "You can also offer linked billing, which lets your customers link their own Claude Console organization to your app and pay Anthropic directly, without sharing an API key." -- [Claude Help Center: Log in to your Claude account](https://support.claude.com/en/articles/13189465-log-in-to-your-claude-account)
- There is no official subscription-backed (Pro/Max) "Sign in with Claude" for third parties. The legal page forbids offering Claude.ai login, and a Mastra issue flags its own "sign in with Claude" (reusing Claude Code's OAuth client) as conflicting. -- [Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance); [mastra-ai/mastra #29198](https://github.com/mastra-ai/mastra/issues/29198)
- Related: Claude Code itself now offers "Sign in with your Console account" (keyless OAuth profile) as an alternative to minting a Console API key. This is first-party only, via `ant auth login` / Claude Code. -- [Claude Code Docs: Authentication](https://code.claude.com/docs/en/authentication)

### Inferences
- Linked billing fits Thought Tidy's *hosted* tier best. Thought Tidy's back end calls Claude, and either Thought Tidy pays (`bill_to: self`, the current hosted subscription) or a BYO-billing user pays (`bill_to: user_profile`). It is a poor fit for the current pure-client BYOK design. The extension and Electron app can only open the auth.claude.com link page. The redirect, token exchange, and every Messages call must go through a Thought Tidy server, which also requires a cloud IdP for WIF.
- Requirements may put off casual users: Admin/Billing role on a Console org, prepaid credits, no Pro/Max subscription usage, and no monthly API credits. For a Pro/Max individual this is "create a Console org and buy credits" with nicer UX than pasting a key, not "use my subscription".
- Because requests run in Thought Tidy's org, user text passes through Thought Tidy's infrastructure. This has privacy-policy implications compared with today's direct-to-Anthropic BYOK.

### Gaps
- The full OAuth reference (redirect-URI rules, e.g. whether `chrome-extension://` or loopback redirects are allowed) was not read. The linked-billing page was only read to 100k of 124k chars, and the testing-period cap and full error table were truncated.
- No primary Anthropic announcement page or release-notes URL was retrieved for the 2026-11-17 launch date.
- Linked Billing Terms text was not read, so it is unknown whether a source-available client is a factor in review.

## 3. "Agent SDK credits" (May 2026): verification, eligibility, attachment; and the Oct 2026 monthly API credits

### Takeaway
Verified that it was announced and then withdrawn. On 2026-05-13 @ClaudeDevs announced that from 2026-06-15, paid plans would claim a separate monthly credit for programmatic use: Agent SDK, `claude -p`, GitHub Actions, and third-party apps built on the Agent SDK. Reported amounts were $20 Pro / $100 Max 5x / $200 Max 20x. On 2026-06-15 Anthropic paused the change, so that usage still draws from subscription limits. Separately, from 2026-10-07 Max, Ultra, and Team plans include **monthly API credits** that go to one linked Console org. These are directly relevant to Thought Tidy's BYOK model.

### Cited Findings
- Announcement text: "Starting June 15, paid Claude plans can claim a dedicated monthly credit for programmatic usage. The credit covers usage of: - Claude Agent SDK - claude -p - Claude Code GitHub Actions - Third-party apps built on the Agent SDK" -- [@ClaudeDevs on X](https://x.com/ClaudeDevs/status/2054610152817619388) (primary social post, superseded)
- Plan amounts ($20 Pro, $100 Max 5x, $200 Max 20x) and later reversal -- [Zed blog](https://zed.dev/blog/anthropic-subscription-changes) (secondary); [GIGAZINE 2026-05-14](https://gigazine.net/gsc_news/en/20260514-anthropic-claude-agent-sdk-credits/) (secondary); [The Decoder](https://the-decoder.com/anthropic-backs-off-unpopular-billing-overhaul-as-price-war-with-openai-looms/) (secondary)
- Reversal (primary): "We've paused the previously-announced changes to Claude Agent SDK usage." Agent SDK, `claude -p`, and third-party app usage "still draw from your subscription limits". -- [Claude Help Center: Use the Claude Agent SDK with your Claude plan](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)
- October 7, 2026 update (primary): Max, Ultra, and Team now include monthly API credits covering the Claude API, Managed Agents, and the Agent SDK / `claude -p` when used with an API key from the linked Console org. "Usage when signed in with your Claude plan is unchanged." -- [Claude Help Center: Use the Claude Agent SDK with your Claude plan](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)
- Amounts: Max $100/mo, Ultra $200/mo, Team $20 per Standard and $100 per Premium seat pooled (cap $500/mo). Free, Pro, and Enterprise are not eligible. Credits are claimable after 7 days on the plan. -- [Claude Help Center: Monthly API credits for Max, Ultra, and Team plans](https://support.claude.com/en/articles/17154008-monthly-api-credits-for-max-ultra-and-team-plans)
- Attachment: claude.ai Billing settings, then "Link organization" in API credits, then choose or create a Console org. "You can link only one Console organization", and the user can't change it. Max/Ultra require the subscriber, Team requires Owner. -- [Monthly API credits](https://support.claude.com/en/articles/17154008-monthly-api-credits-for-max-ultra-and-team-plans)
- Coverage: Claude API, Console Playground, Managed Agents, and the Agent SDK. NOT interactive Claude Code, extra usage, Bedrock/Vertex/Foundry, or "Third-party app usage billed through linked billing". Credits don't roll over and are spent before purchased credits. "Usage is never charged to your Claude plan." -- [Monthly API credits](https://support.claude.com/en/articles/17154008-monthly-api-credits-for-max-ultra-and-team-plans)
- Conflict note: a secondary summary claimed monthly credits can cover linked-billing app usage. Both primary Help Center articles (monthly-credits and linked-billing) say they cannot. -- [Linked billing help](https://support.claude.com/en/articles/18467148-use-your-claude-platform-account-in-a-third-party-app); [Monthly API credits](https://support.claude.com/en/articles/17154008-monthly-api-credits-for-max-ultra-and-team-plans)

### Inferences
- For a Max/Ultra/Team subscriber, the compliant way to have Thought Tidy "draw from my subscription" is: claim monthly API credits into a Console org, create an API key there, and paste it into Thought Tidy (BYOK). API calls with that key consume the $100-$200/mo credit first. This needs no Thought Tidy code change, only onboarding copy. Pro users get no credit and must buy Console credit.
- Somewhat paradoxically, monthly credits work with a pasted API key but NOT with linked billing. For Max users, BYOK is cheaper than linked billing.

## 4. Inverse model: Thought Tidy plugging INTO the user's Claude (connectors, MCP, Claude Desktop extensions, Claude in Chrome); MCP sampling

### Takeaway
The user running Claude in native Anthropic apps (claude.ai, Claude Desktop) with an MCP server or connector from a third party is the sanctioned use of subscription usage ("ordinary use of native Anthropic applications"). However, Claude does **not** support MCP sampling, per Anthropic's help article. So an MCP server cannot "borrow" the user's Claude model to run Thought Tidy's own rewrite pipeline. Claude itself has to do the rewriting inside the Claude chat UI, with Thought Tidy's server providing tools or prompts.

### Cited Findings
- Anthropic's custom connector help article says Claude "does not yet support resource subscriptions, sampling, and other more advanced or draft capabilities". -- [Anthropic Help Center: Building custom connectors via remote MCP servers](https://support.anthropic.com/en/articles/11503834-building-custom-connectors-via-remote-mcp-servers) (as surfaced in search snippet; not fully fetched)
- Conflict: a search snippet of claude.com's connector-building docs appeared to list "Sampling" under a "Supported" heading. This may be a parsing artifact and is unverified. -- [claude.com/docs/connectors/building](https://claude.com/docs/connectors/building.md) (unverified)
- Third-party client matrices conflict. One claims Claude Desktop supports sampling (from v0.7.5), and others say it does not. -- [discord-mcp client matrix](https://cappylab.github.io/discord-mcp/operations/clients/) (secondary); [developersdigest Claude Desktop entry](https://www.developersdigest.tech/mcp-servers/clients/claude-desktop) (secondary, says not supported)
- The MCP spec revision 2026-07-28 deprecates sampling (still functional, eligible for removal on or after 2027-07-28). -- [MCP spec 2026-07-28: Sampling](https://modelcontextprotocol.io/specification/2026-07-28/client/sampling) (as summarized in search results)
- The Messages API MCP connector supports only tool calls from the MCP feature set, and needs public HTTP servers. -- [Claude Platform Docs: MCP connector](https://platform.claude.com/docs/en/agents-and-tools/mcp-connector) (search snippet)
- Subscription usage is for "ordinary use of native Anthropic applications ... including the Claude web, desktop, and mobile applications and Claude Code". -- [Claude Help Center: Log in to your Claude account](https://support.claude.com/en/articles/13189465-log-in-to-your-claude-account)
- `CLAUDE_CODE_OAUTH_TOKEN` subscription tokens "can't ... fetch claude.ai connectors". Claude Desktop uses OAuth and does not read `ANTHROPIC_API_KEY` / `apiKeyHelper`. -- [Claude Code Docs: Authentication](https://code.claude.com/docs/en/authentication)

### Inferences
- Feasible UX: ship Thought Tidy as (a) a remote MCP connector and/or (b) a local Claude Desktop extension (.mcpb) exposing tools/prompts such as "tidy_text(style)", "get_style_profile", "apply_house_rules". The user opens Claude Desktop or claude.ai, pastes or selects text, and invokes a "Tidy" prompt. Claude (on their Pro/Max plan) does the rewriting. Thought Tidy contributes instructions, presets, and possibly post-processing. The UX shifts from "one-click in-page rewrite" to "go to Claude, run a prompt, copy the result back". That gives up the extension's core in-place value.
- Without sampling, the server cannot request completions. Any "Thought Tidy logic" must be expressed as prompts/tool descriptions that Claude follows, or as deterministic tools.
- Paid Pro features could still be gated in the MCP server (license check), because no Claude usage is being resold.

### Gaps
- Not researched in this session (no primary source fetched): .mcpb/.dxt Desktop Extension packaging specifics, the Claude in Chrome extension's extensibility (whether third-party extensions can invoke it; likely not), and "Claude apps"/MCP Apps UI surfaces in claude.ai. Treat these as open questions.
- Whether Claude Desktop's local MCP client advertises the `sampling` capability as of 2026-11 is unresolved. Primary help text says no, and some secondary matrices say yes. A live test would settle it.

## 5. Locally invoking the user's installed Claude Code CLI (`claude -p`) from another desktop app

### Takeaway
The docs explicitly permit an end user to sign in to the **unmodified** Claude Code binary with their own subscription, including when "a platform hosts Claude Code". Embedding or running Claude Code inside a product requires agreeing to the Commercial Terms, and the product must not "pay for, resell, or intermediate" usage. Separately, developers "building products or services ... including those using the Agent SDK, should use API key authentication", and may not "route requests through ... plan credentials on behalf of their users". A user scripting `claude -p` themselves is clearly fine. Thought Tidy (a paid product) spawning the user's subscription-logged-in `claude -p` as its AI backend for text rewriting is not clearly authorized. It conflicts with the spirit of "ordinary use of native Anthropic applications" and "route third-party traffic against subscription limits". Treat it as high-risk unless Anthropic sales confirms in writing.

### Cited Findings
- Carve-out: "Nor does it prevent an end user from signing in to the unmodified Claude Code binary with their own Claude subscription, including where a platform hosts Claude Code as described under *Can customers offer Claude Code in their products?*" -- [Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)
- Embedding conditions: "preinstalling or running Claude Code in your products or services (e.g. in hosted sandboxes or other agent infrastructure) requires agreeing to our Commercial Terms of Service and complying with the conditions below: The Claude Code binary must not be modified ... Customers may not pay for, resell, or intermediate Claude usage on their end users' behalf. Each end user must authenticate with their own Anthropic API key, Claude subscription plan credentials, or 3P inference provider credential". -- [Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)
- Naming: "You can accurately say, in plain text, that your product has Claude Code preinstalled or that it runs Claude Code. But you can't use the Claude Code or Anthropic names or logos as part of your own product, feature, or company name". -- [Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)
- Help Center: tools that "attempt to route third-party traffic against subscription limits ... [are] prohibited and such use may be enforced against." -- [Claude Help Center](https://support.claude.com/en/articles/13189465-log-in-to-your-claude-account)
- `claude -p` with a plan login draws from subscription limits (June 15 pause). With an API key from the linked Console org it uses monthly API credits (Oct 7 update). -- [Use the Claude Agent SDK with your Claude plan](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)
- Auth precedence in Claude Code: cloud provider env, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_API_KEY` ("In non-interactive mode (`-p`), the key is always used when present"), `apiKeyHelper`, `CLAUDE_CODE_OAUTH_TOKEN`, Anthropic profiles, then subscription OAuth from `/login`. -- [Claude Code Docs: Authentication](https://code.claude.com/docs/en/authentication)
- `claude setup-token` creates a one-year subscription OAuth token for "CI pipelines, scripts, or other environments where interactive browser login isn't available". It "requires a Pro, Max, Ultra, Team, or Enterprise plan" and "can only make model requests". `--bare` mode ignores `CLAUDE_CODE_OAUTH_TOKEN`. -- [Claude Code Docs: Authentication](https://code.claude.com/docs/en/authentication)
- Credentials are stored at `%USERPROFILE%\.claude\.credentials.json` on Windows and in the Keychain on macOS. A third party reading these would violate "may not collect, store, or intermediate Claude.ai credentials or session tokens". -- [Authentication](https://code.claude.com/docs/en/authentication); [Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)
- Community precedent (secondary): OpenCode reportedly added a "Claude Agent" provider in Oct 2026 that runs the user's own Claude Code or Agent SDK. Anthropic had not publicly responded. Mastra proposed "run the unmodified Claude Code instead of reusing its OAuth tokens" as the compliant pattern. -- [cellcog.ai](https://cellcog.ai/blog/opencode-claude-subscription/) (secondary); [mastra-ai/mastra #29198](https://github.com/mastra-ai/mastra/issues/29198)

### Inferences
- Safe for Thought Tidy desktop: spawn `claude -p` only when the user has configured it with an **API key** (their own Console key, or monthly-credit org key). Then usage is billed to the key owner, which is explicitly allowed. This adds little over calling the Messages API directly.
- Risky: spawning `claude -p` on the user's subscription login to power a paid rewrite feature. The binary is unmodified and the user's own login is used, so it fits the literal carve-out. But Thought Tidy is a product "interact[ing] with Claude's capabilities", and a writing assistant is not "ordinary use of Claude Code". Anthropic reserves enforcement "without prior notice", and the enforcement target would be the user's account. If offered at all, it should be an opt-in "Advanced: use my local Claude Code" with clear disclosure. Ideally get written confirmation from Anthropic first (the legal page points to "contact sales").
- Not applicable to the browser extension, which cannot spawn processes (native messaging would be required).

### Gaps
- No primary Anthropic statement directly addresses "a desktop app shells out to the user's locally installed, subscription-authenticated `claude -p`". The answer above is an interpretation of the two clauses.
- Headless docs (code.claude.com/docs/en/headless) were not fetched separately. The auth behaviour comes from the Authentication page.

## 6. Anthropic API features for browser use: CORS header, workspace keys, spend limits ("set up once" UX)

### Takeaway
Direct browser calls to the Messages API work if the request includes the `anthropic-dangerous-direct-browser-access: true` header (added Aug 2024). This is acceptable for BYOK, where the user's own key sits in their own browser. For a set-up-once UX, a dedicated Console workspace/key with a spend limit, optionally funded by Max/Ultra/Team monthly API credits, gives guardrails without any Thought Tidy server. Linked billing provides per-app spend caps but needs a back end.

### Cited Findings
- CORS support was added in August 2024 via the `anthropic-dangerous-direct-browser-access: true` request header. Without it, browser requests fail with a CORS authentication error. -- [Simon Willison, 2024-08-23](https://simonwillison.net/2024/Aug/23/anthropic-dangerous-direct-browser-access) (secondary, older info); [NextChat issue #5452](https://github.com/ChatGPTNextWeb/NextChat/issues/5452) (secondary)
- The header name signals that keys in front-end code are visible via devtools. Community consensus is that it is acceptable for BYOK only. -- [DEV Community BYOK post](https://dev.to/sendotltd/calling-the-anthropic-api-directly-from-the-browser-a-150-line-byok-comparison-tool-for-opus--nh) (secondary)
- Reported limit: orgs with ZDR or the Compliance API enabled reject requests carrying the workspace header even with the browser-access header. -- [Claude Lab article](https://claudelab.net/en/articles/api-sdk/claude-api-valid-key-400-401-workspace-header-cors-triage) (secondary; claims to cite docs)
- Linked billing offers per-app spend caps set by the user in the Console ("Linked platforms" page), 80%/100% emails, and a 402 when the cap is exhausted. -- [Claude Help Center](https://support.claude.com/en/articles/18467148-use-your-claude-platform-account-in-a-third-party-app)
- Monthly API credits are spent before purchased credits. When exhausted with no other credit, "API requests pause until the next grant". This acts as a natural hard cap for credit-only orgs. -- [Monthly API credits](https://support.claude.com/en/articles/17154008-monthly-api-credits-for-max-ultra-and-team-plans)

### Inferences
- Recommended BYOK onboarding copy for Thought Tidy: "Create a Console workspace named Thought Tidy, set a monthly spend limit, create a key, and paste it. If you're on Max/Ultra/Team, link your monthly API credits org first so Thought Tidy usage comes out of your included $100-$200/mo." This is fully compliant, works in both extension and desktop, and needs no server.
- For Electron, calling from the main process (Node) avoids needing the dangerous-browser header and keeps the key out of the renderer. For the extension, a background service worker call is still "browser" and needs the header.

### Gaps
- I did not fetch Anthropic's current primary docs on the CORS header, workspace-level spend limits, or per-key restrictions in Console (Nov 2026). The CORS details above rest on 2024 secondary sources. Verify against platform.claude.com API docs.
- No evidence found of an OpenRouter-style flow that mints and returns a raw API key to a public client (extension/desktop) via PKCE. Linked billing deliberately never gives the app a key.
